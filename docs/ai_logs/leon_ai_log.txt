Docker & DB Infrastructure
    Date: 2/14/2026
    Tool: Claude (claude-sonnet-4-6)
    Purpose: Understand Docker Compose healthcheck behaviour

After adding the retry logic and healthcheck, the backend was still timing out on startup in some cases. I wasn't sure if the issue was with pg_isready or with how service_healthy works.

I asked Claude about:
    1. What service_healthy actually waits for vs service_started
    2. Whether pg_isready is reliable as a healthcheck or if a real query is safer
    3. What the timeout and retries fields in healthcheck do

Claude explained that pg_isready only checks if the socket is open, not if Postgres is ready to take queries. That helped me understand why timing issues were still happening. I used that to decide what to adjust in the config myself.

Claude helped me understand the concepts — all the actual changes and testing were done by me.

Task API Debugging
    Date: 2/21/2026
    Tool: OpenAI Codex (gpt 5.2)
    Purpose: Debug a silent failure in the PATCH /api/tasks/:taskId endpoint

The PATCH endpoint was returning 200 OK but the is_complete field wasn't updating in the database in some cases. I suspected a type issue somewhere between the frontend and the SQL query.

I pasted the relevant part of server.js into Codex and asked it to spot any potential issues. Codex pointed out that isComplete from req.body was going straight into the query without explicit type casting, which could cause silent failures with the pg driver.

That gave me a clear direction to investigate. The actual fix — adding an explicit boolean cast before passing the value to pool.query — was written and tested by me.

Codex helped me find where to look. The endpoint logic and all the SQL were my own work.
